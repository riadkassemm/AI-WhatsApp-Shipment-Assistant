What this change implements
---------------------------
storage.js retains private version-2 failure evidence using the existing atomic
write/fsync/rename/directory-fsync path and mode 0600:
- final mutable credentials at failure and subsequent settlement;
- owner epoch, connection/auth generation, committed sequence and revision;
- pending provider/credential/journal writes and retired status;
- fixed operation source labels (mutex / bridgeTask / detached task / key call);
- separate provider-body and wrapper outcomes: not_started, unresolved,
  completed or rejected (a returned body is not proof of a successful commit);
- final transport-close promise and event-subscription release evidence.
Only operations outstanding at failure are retained, not lifetime task history.
Healthy operation does not add new evidence-file writes.

A timeout-deactivated, already admitted callback now preserves rejected late
keys before being refused. It still cannot commit or revive a retired owner.
Evidence write failure remains a permanent review blocker even if a later
queued snapshot writes successfully. Reads observe the latest evidence tail,
with a one-second observation bound; stalled evidence I/O returns BLOCKED.

bridge.js retains retiring-generation diagnostics with their original generation
and retiring_generation=true. Those callbacks cannot overwrite newer health or
claim successful recovery. Existing close barriers and reconnect policy remain.

Private authenticated GET /v1/lines/90011/auth-recovery is observation only.
It does not replay journals, flush a store, invoke the provider, change markers,
create a replacement owner or submit a message. It returns fixed labels/counts
and an evidence_reference derived ONLY from a random owner epoch and counters.
No credentials, keys, credential fingerprints, customer data or raw errors leave
the process. The private failure file must never be served, logged or exported.

auth-recovery-inspect.js reads an already preserved identity copy, checks private
permissions and stable file hashes, and replays with repairTail=false. It does
not load/create a JournalStore or acquire/replace the bridge directory lock.
Legacy, incomplete, changed or corrupt evidence blocks assessment. It cannot
repair changed keys or uncertain fsync outcomes merely because bytes look valid.

Assessment meaning
------------------
BLOCKED: a mandatory authentication proof is missing or disagrees.
OPERATOR_REVIEW_REQUIRED: authentication evidence from this private copy meets
the narrow zero-mutation review criteria. This is NOT recovery authorization.
recovery_allowed is ALWAYS false; no recovery mutation endpoint is implemented.
The live endpoint always requires separate offline journal validation.

An offline copy cannot prove current exclusive ownership. Require a fresh live
assessment with the SAME evidence_reference, no ownership transition, and only
OFFLINE_JOURNAL_VALIDATION_REQUIRED outstanding. Also require the independent
database/Redis/callback checks below. A copied successful assessment, old PID,
socket disappearance or "paired" status is never an authorization token.
